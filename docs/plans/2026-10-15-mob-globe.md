# Mob Globe Implementation Plan

> Work through tasks in order; tick the boxes as you go. Each task ends in a commit.

**Goal:** Take the sandbox-written Mob Globe (live Solana buy/sell tracker on a 3D globe) from "never run against real traffic" to live, persisted in Supabase, deployed, with Telegram alerts.

**Architecture:** Single Node 18+ ESM relay (`server.js`) fans PumpPortal + Helius (`logsSubscribe` -> `getTransaction`) trades out over a WebSocket at `/stream`; single-file `index.html` renders the globe. New: pure decode/region/bot logic extracted into `lib/` so it can be unit-tested from recorded fixtures; a batched Supabase writer; read-only browser access to aggregate tables.

**Tech stack:** Node ESM, `ws`, `node:test` (no new test dependency), `@supabase/supabase-js` (relay only), Supabase Postgres.

**Hard rules (from `mob-globe/CLAUDE.md`, apply to every task):** visual tracker only (no scoring/advice); regions are labelled "estimated"; secrets only in server `.env`; use supplied artwork unchanged; flag FCA crypto-promotion if the app ever promotes a token or paid signals.

**Location:** the handoff is copied into `mob-globe/` in this repo (separate app, separate `package.json`, separate accounts from Agentlaunch). If you'd rather it live in its own repo, only Task 0 changes.

## Task 1: Run it live (DEMO -> LIVE)

**Files:** `mob-globe/server.js`, `mob-globe/index.html`, new `mob-globe/test/fixtures/*.json`

- [ ] `cd mob-globe && npm install && npm start` with `HELIUS_KEY` set. Confirm the badge flips DEMO -> LIVE in a headless Chromium screenshot (Playwright is preinstalled).
- [ ] **Record real traffic** for ~2 min: add a `RECORD=1` env flag that appends raw PumpPortal messages, Helius `logsNotification` messages and 10-20 raw `getTransaction` results to `test/fixtures/`. Commit trimmed fixtures (no keys; URLs in fixtures are scrubbed).
- [ ] Verify each assumption against the recordings and fix: PumpPortal fields (`txType`, `solAmount`, `traderPublicKey`, `signature`, `mint`, `symbol`, `uri`); DexScreener/CoinGecko shapes; Helius rate limit (10 req/s) and credit burn at `DECODE_PER_SEC=0.4` (check the Helius dashboard after 10 min); websocket bandwidth from subscribing to busy programs (Jupiter) - if heavy, subscribe only to a sampled subset.
- [ ] Known suspects to check while there: `getTransaction` signer is `accountKeys[0]` (ok for fee payer, wrong for relayer-paid txs); Jito tip skew; token-for-token swaps skipped; logo `toDataURL` canvas taint -> add `/logo?u=` proxy in the relay (allowlisted hosts only) and use it in `index.html`.
- [ ] **Extract for testing**: move `touch/pick/act` (region + bot) and the balance-delta part of `decode` into `lib/region.js` and `lib/decode.js` as pure functions (`decodeSwap(tx, solUsd) -> {mint,buy,usd,venue,signer}|null`). `server.js` imports them; behaviour unchanged.
- [ ] **Tests** (`test/decode.test.js`, `test/region.test.js`, run with `node --test`): fixture buy, fixture sell, token-for-token skipped, failed tx skipped, <$10 skipped, USDC quote, bot rule (8 trades/60s; 15 trades over 16+ hours), region pick (1-2 trades weighted, 3+ best match). Write each test first against a fixture, watch it fail, then fix.
- [ ] Add `"test": "node --test"` to `package.json`.
- [ ] Commit: `mob-globe: run live, fixtures + decode/region tests`. Report what changed and observed behaviour.

## Task 3: Supabase schema + persistence

**Files:** `mob-globe/supabase/schema.sql`, new `mob-globe/lib/store.js`, `mob-globe/test/store.test.js`, `server.js`

- [ ] **Review the draft schema before applying.** Fixes: `primary key (bucket, mint, venue, region)` fails if `venue` is null -> `not null default ''`; add `hourly_flow` rollup table; add a `config` read policy only where the browser needs it; confirm `wallet_stats`/`tracked_wallets` have RLS on and no policies (service role only).
- [ ] **Ask you before applying** (it touches your new project). Apply via Supabase SQL editor (paste) or CLI with your confirmation.
- [ ] `lib/store.js`: in-memory accumulator keyed `(minute, mint, venue, region)`; `flush()` every 5s does one upsert batch (`flow_minute`), inserts `big_trades` (>= $5k, `on conflict (sig) do nothing`), upserts changed `wallet_stats`. Failure -> keep the buffer, retry with backoff, cap buffer size (drop oldest). Relay must keep running if Supabase is down.
- [ ] Tests with a fake client: aggregation math, flush batching, retry-on-failure keeps data, buffer cap.
- [ ] Load `wallet_stats` and `tracked_wallets` on boot (region/bot survive restarts); sync pins to `tracked_wallets` (cap 50, B58 validated). Note: pins are currently per-browser; with no auth, treat tracked wallets as global for this single-owner app and say so in the UI.
- [ ] Hourly rollup + retention: `pg_cron` job to roll `flow_minute` older than 7 days into `hourly_flow` and delete `big_trades` older than 30 days.
- [ ] Browser read-only: serve anon URL/key to the page via the relay's `/config` (anon key is public by design; never the service key). `index.html` reads daily/weekly flow from `hourly_flow`/`flow_minute` and draws charts in the existing style, labelled "estimated" by region.
- [ ] Commit. Verify rows land in Supabase after 2 min live.
